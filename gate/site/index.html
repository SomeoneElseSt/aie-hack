SubQ as an independent merge gate for AI code reviewers

AI reviewers flag real bugs, but most of their comments are noise. We used SubQ Snap to check each review comment and block the false alarms, then measured the result on a public benchmark.

CodeRabbit + SubQ gate: precision 0.31 → 0.56, F1 +0.106 on held-out PRs. SubQ improved 12 of 21 reviewers and never cost more than 0.014 F1.

Setup

  • Benchmark: Martian Code Review Bench. 50 real PRs from Sentry, Grafana, Cal.com, Discourse and Keycloak with human-verified bugs, plus the stored comments of ~20 AI reviewers and judge labels (Claude Opus 4.5) for each comment.
  • Gate: for every comment, SubQ Snap (Decisions API, subq-snap-1.1) reads the PR diff and answers “is this a real defect introduced by this diff?” with a probability. Comments below a cutoff are blocked.
  • Scoring: a blocked real bug becomes a miss; a blocked false alarm disappears. Bug/security/data/concurrency/API issues only (strict profile).
  • No cherry-picking: the cutoff is chosen on 25 PRs and scored on the other 25, then the halves swap. The gain column averages both.

What it means

  • The noisier the reviewer, the bigger the gain. Every reviewer with precision under 0.45 improved, by up to +0.106 F1.
  • Reviewers that already filter their own comments (Greptile, Macroscope, Qodo-extended) gain nothing, which tells a team which reviewers need a gate.
  • The gate trades a little recall for a lot of precision. For Claude, precision rose 0.41 → 0.70 while recall fell 0.40 → 0.34; F1 is the net effect.

Limits

  • Our key only has SubQ Snap (decisions). The text-generating model subq-preview is early access and was not available, so SubQ gates comments rather than writing its own.
  • 20 older tool versions in the benchmark lack bug-category labels and were excluded; their current versions are in the table.
  • A run giving SubQ the full changed files (long-context) is in progress.
